What Gen1 must demonstrate

The Gen1 programme is built to prove the core principles of state-resident structural computing on real hardware before any tape-out commitment. The proof-of-concept demonstrates two claims:

  • Topology. State moves between nodes on a compile-time schedule with no runtime routing.
  • Timing. Latency is pipe depth — it changes only by the amount a physical change (fiber length) predicts.

Everything else — throughput at workload level, power, economics — is quantified later and published with its configuration. No tokens/sec or cost figures are claimed at this stage.

Measurement methodology

  • Identical cycle count across repeated runs of the same workload under the same configuration
  • Latency shift measured against fiber-length changes (10 / 50 / 100 / 500 m), compared with predicted values
  • No jitter, no retries tolerated in a passing run
  • Every run logged with its full configuration for reproducibility

Where the MPU fits, stated honestly

Single-stream decode throughput is bounded by memory bandwidth. The MPU case is conditional and specific: state-resident computing targets mixture-of-experts / sparse serving, long-context workloads, and latency-bound single-stream serving — not dense large-batch serving, where HBM-based GPUs win on bandwidth per dollar.
